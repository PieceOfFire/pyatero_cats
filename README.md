# Пятеро котят

Отдельный асинхронный Telegram-бот для коллекционирования котят. Python 3.11+, aiogram 3, aiohttp, asyncpg. Размещение: **Render Web Service → Neon PostgreSQL → Telegram file_id**. Облако Mail используется для импорта оригиналов и хранения резервных копий.

Проект находится в `C:\NSU\TBC\pyatero_cats`. Существующий `cats` не изменялся. Аккаунты сервисов не созданы, бот не опубликован, реальные токены и данные из старого проекта не копировались.

## Что работает

- `/start` — главное инлайн-меню оригинального режима: «Спин», «Награды», «Сменить ник», «Лидерборд». Дополнительно доступны коллекция, профиль и ссылка группы.
- Навигация редактирует текущее текстовое меню, в подменю есть кнопки «Назад».
- `/cat` или кнопка — новый котёнок за один спин, без повторов в коллекции.
- Редкости COM/UCOM/RARE/EPIC/LEG: веса 60/25/10/4/1, очки 1/3/7/20/50. Если выбранная редкость уже собрана, выбирается случайная оставшаяся карточка, как в старом боте. Итоговые вероятности поэтому меняются по мере заполнения коллекции.
- `/daily` или «Награды → Ежедневная» — награда один раз в сутки (Asia/Novosibirsk). Стрик как в оригинале: дни 1–3 дают +1, дни 4–6 — +2, с 7-го — +3. Пропущенный день сбрасывает стрик. Игры 3×3 нет.
- «Награды → За подписку» — одноразовая награда за настроенный канал, с проверкой членства Telegram.
- «Награды → Ввести промокод» или `/promo КОД` — одноразовое получение бонуса для каждого пользователя.
- «Сменить ник» позволяет выбрать @username или ввести ник сообщением. Состояния ввода хранятся в PostgreSQL и переживают рестарт Render; срок ожидания 30 минут.
- `/collection` — список с перелистыванием; `/last` — бесплатная повторная отправка последней выдачи.
- `/top`, `/nick имя`, `/id`, `/help`.
- Администратор добавляет фото прямо в Telegram; есть массовый CSV-импорт из локальных файлов и Mail WebDAV.
- Импорт старых пользователей, коллекций, спинов и очков из CSV.
- Команда резервного копирования PostgreSQL с загрузкой в Mail.

Начальный баланс — 3 спина, максимальный — 999; значения задаются через окружение. `DAILY_REWARD_MODE=streak` включает оригинальную схему ежедневной награды. Для постоянного бонуса задай `DAILY_REWARD_MODE=fixed` и `DAILY_SPINS=3`.

Новогодний режим и игра 3×3 не переносились по запросу. Старые флаги активации промокодов и бонуса за подписку пока не импортируются: для возобновления старых акций понадобится их отдельный перенос. Для новой акции используй новые коды.

## Администратор и награды

В локальном `.env` уже есть пустое поле `ADMIN_ID=`. Вставь туда свой **числовой Telegram ID**, который выдаёт `/id`. Это не код входа в Telegram и не @username. На Render добавь тот же `ADMIN_ID` в **Environment**; Blueprint уже содержит это поле. Для нескольких администраторов используй дополнительный `ADMIN_IDS=123,456` (старое имя настройки поддерживается).

После изменения окружения перезапусти приложение. Только указанным ID показывается кнопка входа в админский режим. Команда `/admin` или эта кнопка включает режим на 12 часов. `/adminoff` или кнопка выхода выключает его. Удаление ID из настроек после перезапуска закрывает доступ, даже если сессия ещё не истекла.

Админ-панель позволяет добавлять и обновлять котят, скрывать карточки из новых выдач и возвращать их, создавать и отключать промокоды, видеть использование кодов и общую статистику. Скрытие сохраняет коллекции пользователей. Проверка ID и активного режима выполняется для команд, callback-кнопок и ответов в диалогах; подделанная callback_data доступа не даёт.

Создать промокод: включи `/admin`, затем выбери кнопку или отправь `/promocreate CATS2026 | 5 | Подарок от группы`. Пользователь вводит `CATS2026` через меню или `/promo CATS2026`. Код регистронезависимый, действует один раз на каждого пользователя. Повторные запросы не начисляют бонус дважды. Отключённые коды не работают; существующий код нельзя перезаписать повторным созданием. При полном балансе код не расходуется; при частичном заполнении бонус ограничивается максимальным балансом.

Для награды за подписку задай `BONUS_CHANNEL=@username_канала` и `SUBSCRIPTION_SPINS=3`. Добавь самого бота администратором канала: приложение проверяет его права перед начислением. Для закрытого канала укажи числовой `BONUS_CHANNEL=-100…` и приглашение `BONUS_CHANNEL_URL=https://t.me/+…`. Без настройки канала кнопка подписки скрыта. Награда выдаётся один раз для пары пользователь/настроенный канал.

SQL-миграция 002 применяется автоматически, сохраняя таблицы и коллекции первой версии. Исходный `schema.sql` менять или повторно вручную выполнять не нужно. Админские сессии и состояния ввода хранятся в базе.

## Быстрый локальный запуск

1. Создай бота через @BotFather либо используй токен нужного существующего бота. `file_id` одного бота не подходит другому. База фиксирует ID бота и откажет в подключении с другим ботом.
2. Создай проект в [Neon](https://neon.com/). В **Connect** выбери PostgreSQL и pooled connection string. Скопируй URL с `sslmode=require` в `.env`. Параметр `channel_binding`, встречающийся в ссылках Neon, автоматически убирается для совместимости с asyncpg; TLS остаётся включённым.
3. В PowerShell:

```powershell
cd C:\NSU\TBC\pyatero_cats
# Окружение .venv уже создано при подготовке проекта.
# На другом компьютере: py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
```

4. Открой `.env`, заполни `BOT_TOKEN` и `DATABASE_URL`, оставь `MODE=polling`.
5. Запусти:

```powershell
.\.venv\Scripts\python.exe -m catbot
```

Схема создаётся автоматически. Напиши боту `/start`, затем `/id`. Впиши свой числовой ID в `ADMIN_ID` и ID личного чата в `MEDIA_CHAT_ID`, перезапусти приложение. Затем включи `/admin`. Для личного чата сначала нужно написать боту, чтобы он мог отправлять туда импортируемые фотографии.

При добавлении карточек вручную `MEDIA_CHAT_ID` не обязателен: включи `/admin` и отправь боту фото с подписью:

```text
/addcat cat001 | RARE | Котёнок, который пришёл на репетицию
```

Можно ответить такой командой на уже присланное фото. Повтор того же ID обновляет описание, редкость и фото карточки, сохраняя коллекции пользователей. Исходник для архива Mail сохраняй отдельно: Telegram-фото может быть сжато.

## Render: публикация

1. Создай отдельный GitHub-репозиторий и помести **содержимое этой папки в корень**. Не загружай `.env`, `.venv`, дампы и личные CSV. Папки `.github` и файл `render.yaml` должны попасть в репозиторий.
2. В Render выбери **New → Blueprint**, подключи репозиторий. Blueprint создаёт только бесплатный Web Service; база остаётся в Neon.
3. Введи `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_ID`, `MEDIA_CHAT_ID`. Render сгенерирует `WEBHOOK_SECRET`, `MODE=webhook` задан в Blueprint. Внешний адрес берётся из `RENDER_EXTERNAL_URL` автоматически. Не нужно добавлять webhook вручную.
4. Дождись успешного deploy. Health endpoint: `https://ИМЯ.onrender.com/healthz`.
5. Останови локальный polling перед запуском Render: polling удаляет webhook, поэтому один токен нельзя одновременно использовать в двух режимах.

Если создаёшь сервис вручную:

```text
Runtime: Python 3.11
Build: pip install -r requirements.lock.txt
Start: python -m catbot
Health check: /healthz
MODE=webhook
WEBHOOK_SECRET=<случайная строка минимум 32 символа>
```

Секрет можно получить локально: `.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"`. `BAND_URL` добавляет кнопку группы: укажи реальную HTTPS-ссылку. Пароль Mail нужен только на компьютере, с которого запускаются импорт и backup; для повседневной работы Render он не нужен.

Если публикуешь как подпапку существующего репозитория, укажи Root Directory `pyatero_cats` в Render и скорректируй пути workflow. Приложенный Blueprint и workflow рассчитаны на отдельный репозиторий.

**Ограничение бесплатного Render:** сервис засыпает после 15 минут без входящих запросов. Первое сообщение после сна может ждать около минуты; Telegram повторяет неуспешную доставку webhook. Перевод на webhook позволяет разбудить сервис, но не устраняет холодный старт. Файлы времени выполнения на Render временные: в них не хранится игровое состояние. Health endpoint не опрашивает Neon и не расходует вычисления базы.

Neon Free имеет лимиты хранения, вычислений и трафика. При исчерпании квоты бот может стать недоступен; тариф без гарантии постоянной доступности. Актуальные условия: [Render Free](https://render.com/docs/free), [Neon](https://neon.com/pricing).

## Импорт каталога и старых пользователей

Импорт запускай со своего компьютера, используя тот же `.env`, тот же токен и ту же базу, что у Render. Это отдельная служебная команда, она не запускает polling и не меняет webhook.

Подготовь CSV по образцу `data/catalog.example.csv`. Поля: `id,description,rarity,telegram_file_id,local_path,mail_path`. Для строки нужен ровно один источник:

- `telegram_file_id` — фото, уже полученное **этим ботом**;
- `local_path` — локальный файл, относительный путь считается от CSV;
- `mail_path` — путь в твоём Облаке Mail, например `/Котята/cat002.jpg`.

Столбец `DESC` старого каталога также поддерживается. Старый `URL` Google Drive автоматически не скачивается: сначала скачай оригиналы или перенеси их в Mail и укажи соответствующие пути. Пример CSV содержит вымышленные пути: замени их реальными.

Для Mail заполни в `.env`:

```dotenv
MAIL_USER=you@mail.ru
MAIL_APP_PASSWORD=пароль_внешнего_приложения
```

[Официальная настройка WebDAV Mail](https://help.mail.ru/cloud/desktop/webdav/). Скрипт использует фиксированный адрес `https://webdav.cloud.mail.ru/`; общедоступные ссылки не нужны. Фото для Telegram должно быть допустимым JPEG/PNG, не больше 10 МБ и соответствовать ограничениям Telegram по размерам изображения.

```powershell
.\.venv\Scripts\python.exe -m catbot.tools import-cats data/catalog.csv
.\.venv\Scripts\python.exe -m catbot.tools import-users data/users.csv
```

При импорте каждый оригинал один раз отправляется в служебный чат, затем сохраняется `file_id`. При ежедневной выдаче запросов к Mail/Google нет. Импорт каталога сохраняется построчно: после сбоя можно повторить; карточки обновятся по стабильному ID. Повторный запуск импорта с оригиналами повторно загрузит фото в служебный чат. Удали пробные карточки перед окончательной миграцией или используй отдельную тестовую базу.

Импорт пользователей: поля старой таблицы `USER_ID,NICK,CATS_ID,SPINS,LAST_DAILY,SUM` и необязательный `STREAK` для сохранения серии ежедневных входов. Дата — `YYYY-MM-DD`, коллекция — ID через `|`, пробел, запятую или `;`. Сначала импортируй всех котят, сохранив старые ID. Неизвестный ID, некорректная дата или баланс отменяют весь импорт пользователей; существующие пользователи пропускаются целиком. Если `SUM` пуст, очки считаются по редкостям коллекции. История отдельных выдач старой версии не восстанавливается.

Для финального переноса останови старого бота, экспортируй его таблицы и импортируй в новую базу **до первого запуска для пользователей**. Если старый токен когда-либо был опубликован, перевыпусти его в BotFather. Не копируй ключи Google в этот проект.

## Резервные копии в Mail

Нужен установленный `pg_dump` той же или более новой основной версии, чем PostgreSQL в Neon. В `.env` укажи **direct connection string** Neon в `PG_DUMP_DATABASE_URL` (для работы бота оставь pooled `DATABASE_URL`). Если `pg_dump` отсутствует в PATH, укажи полный путь в `PG_DUMP_PATH`.

```powershell
.\.venv\Scripts\python.exe -m catbot.tools backup
.\.venv\Scripts\python.exe -m catbot.tools backup --mail
```

Дамп сохраняется в `backups/`; с `--mail` он также загружается в `/pyatero-cats/backups`. Внешний `pg_dump` ожидается асинхронно; загрузка идёт частями, чтение файлов вынесено из event loop. Пароль базы передаётся через окружение дочернего процесса. Это дамп данных, **не работающая база на WebDAV**. Каталог содержит ссылки на оригиналы, сами картинки в дамп не входят.

Автоматическое расписание не установлено. Для ежедневной копии добавь эту команду в Планировщик Windows с рабочей папкой проекта и полным путём к Python. Компьютер должен быть включён. Файлы не удаляются автоматически: следи за местом и сроком хранения, доступ к дампам должен быть закрытым.

Восстановление выполняется утилитой `pg_restore` в отдельную пустую базу. Сначала восстанови тестовую копию, проверь пользователей и коллекции, затем меняй `DATABASE_URL`. Не восстанавливай поверх работающей базы. Повторные `file_id` работают только с исходным ботом.

## Асинхронность и поведение при сбоях

- aiohttp принимает webhook, aiogram обрабатывает команды, asyncpg использует небольшой пул соединений. Нет синхронного Google API в обработчиках.
- Одновременно обрабатывается до 8 обновлений; пул PostgreSQL по умолчанию до 5 соединений. Лимиты настраиваются.
- При выдаче строка пользователя блокируется `FOR UPDATE`. Спин, карточка и очки записываются одной короткой транзакцией. Запрос к Telegram выполняется после завершения транзакции.
- `rolls.update_id` хранит результат выдачи. Повтор того же обновления возвращает того же котёнка, не списывая новый спин. Два разных нажатия — две отдельные выдачи, если хватает спинов.
- Webhook проверяет секретный заголовок Telegram. HTTP 200 отправляется после завершения обработчика. При ошибке — 503, чтобы Telegram мог повторить доставку.
- Обработка ограничена 45 секундами, lease обновления — 90 секунд. После падения процесса повторная доставка сможет забрать истёкший lease. Завершённые обновления повторно не обрабатываются.
- Между PostgreSQL и Telegram нет общей транзакции. Если Telegram принял фото, но ответ потерялся, повторная доставка может показать фото ещё раз. Коллекция и баланс при этом не меняются повторно. `/last` также повторяет фото бесплатно.
- При недоступном `file_id` котёнок остаётся в коллекции; администратор может обновить фото тем же ID, пользователь — повторить `/last`. Автоматической загрузки оригинала на каждый сбой нет.
- Дополнительных Redis, диска Render и фоновых keep-alive запросов нет. Копии и очистка запускаются отдельно: `python -m catbot.tools prune` удаляет только receipts старше 7 дней; история выдач сохраняется.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest -q
```

Без PostgreSQL тесты транзакций пропускаются. Для них создай отдельную **пустую тестовую базу**. Не используй рабочую Neon-базу: тесты создают и удаляют свои таблицы. PostgreSQL можно запустить через приложенный Docker Compose:

```powershell
docker compose up -d
docker compose exec db createdb -U cats cats_test
$env:TEST_DATABASE_URL="postgresql://cats:cats_local_only@localhost:5432/cats_test?sslmode=disable"
.\.venv\Scripts\python.exe -m pytest -q
```

GitHub Actions уже настроен на PostgreSQL 17 и все тесты: параллельные спины, однократный daily, повторный update_id, откат транзакции, привязка бота и receipts. Пока проект не загружен в GitHub, workflow не выполнялся. Реальные Telegram, Neon и Mail требуют отдельной проверки после заполнения ключей.
